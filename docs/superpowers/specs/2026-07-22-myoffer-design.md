# MyOffer 设计方案

日期：2026-07-22
状态：已确认，待实现

## 背景与目标

个人使用的秋招信息汇总工具，运行在本机浏览器（`localhost`），不需要账号系统。用户在一个页面里：
- 维护一份公司信息库（类型、规模、是否开启27秋招、招聘网址）
- 追踪自己在不同公司/岗位下的投递进度
- 维护一份可复制粘贴的简历模块库，方便手动填写不同公司的招聘系统

## 使用范围

单用户本地工具。无登录、无多用户隔离、无云端部署。数据存放在本机 SQLite 文件里。

## 技术栈

- 后端：FastAPI + SQLAlchemy(ORM) + SQLite（单文件数据库 `myoffer.db`）
- 前端：Jinja2 服务端模板 + HTMX 做无刷新增删改；Alpine.js 仅用于"复制到剪贴板"这类纯客户端交互
- 不引入 npm / 前端构建工具链
- 简历原始文件（如果保留）存本地 `uploads/` 目录，路径记录在数据库

启动方式：`uvicorn app.main:app --reload`，浏览器打开 `localhost:8000`。

## 通用设计模式：预设选项 + 自定义新增

行业类型、base城市、投递阶段、简历模块分类这几个字段都遵循同一模式，且不建单独的字典表：

- 代码里维护一份默认选项常量（如 `DEFAULT_INDUSTRIES = ["互联网","游戏","金融","消费","制造","其他"]`）
- 下拉框可选项 = 默认列表 ∪ 数据库里已出现过的值（`SELECT DISTINCT`）
- 用户输入新值时直接存成字符串，写库前 `.strip()`，下次自动出现在下拉选项里
- 取舍：不需要额外的字典管理页面，新增即用；代价是没有防呆去重（"互联网" 和 "互联网 " 会被当成两个不同值，只做基本的 strip 处理，不做更复杂的归一化）

## 数据模型

### Company（公司）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int, PK | |
| name | string | 公司名 |
| industry | string | 类型（预设+自定义，如互联网/游戏/金融） |
| scale_tags | JSON list | 规模标签，多选（是否上市/世界500强/中国500强/独角兽等，checkbox，可自定义新增标签） |
| recruiting_open | bool | 是否开启27秋招 |
| recruiting_url | string, 可空 | 秋招网址链接 |
| notes | text, 可空 | 备注 |

### Application（投递记录）

一个公司可对应多条投递记录（同公司投多个岗位）。"是否已投递"不是独立字段，而是"该公司名下是否存在 Application 记录"这一派生状态。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int, PK | |
| company_id | FK → Company | |
| position | string | 岗位（预设常见岗位+自定义输入） |
| base_city | string | base地（预设城市+自定义） |
| stage | string | 当前进展（预设阶段：未投递/已投递/笔试/测评/一面/二面/三面/HR面/offer/已拒/已弃 + 自定义） |
| applied_date | date, 可空 | 投递日期 |
| updated_at | datetime | 最后更新时间，改 stage 时自动刷新 |
| notes | text, 可空 | 备注（面试反馈等） |

### ResumeModule（简历模块）

每个模块只有一个版本（不支持多版本变体，需要不同版本时用户手动复制新建一个模块）。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int, PK | |
| category | string | 分类（预设：基本信息/教育经历/实习经历/项目经历/技能特长/荣誉奖项/自我评价 + 自定义） |
| title | string, 可空 | 模块标题（如具体项目名） |
| content | text | 正文（用户手动粘贴/编辑） |
| sort_order | int | 显示顺序，支持上下移动调整 |

## 页面与核心交互

### 页面一：公司库（首页）

- 列表展示公司：名称、类型、规模标签、是否开启27秋招（视觉标记）、秋招链接（新标签页打开）
- 顶部筛选：按类型 / 是否开启秋招 / 是否已投递
- 每行显示"是否已投递"派生状态
- 行内"+ 新增投递"：HTMX 局部表单展开，提交后无刷新插入投递记录
- 公司信息新增/编辑/删除走同一表格的编辑弹层，删除公司时若存在关联投递记录需二次确认（级联提示"该公司下还有N条投递记录，确认一并删除？"）

### 页面二：我的投递看板

- MVP 用列表 + 按阶段筛选（看板视图后续可加，本期不做）
- 每条记录内联修改阶段（下拉选择，选中即 HTMX 提交更新，`updated_at` 自动刷新）
- 点击记录展开查看备注/投递日期详情

### 页面三：简历模块库

- 左侧分类导航，右侧该分类下模块卡片列表
- 每个卡片：标题 + 正文预览 + 「复制」按钮（Alpine.js 调 `navigator.clipboard.writeText`，纯前端不请求后端）+ 编辑/删除按钮
- 新增模块：选分类（或新建分类）→ 填标题 → 粘贴正文 → 保存
- 支持同分类下模块顺序上下移动（更新 sort_order）

## 初始数据

- `app/seed_data.py` 整理常见互联网/游戏/金融等头部公司的**名称、行业类型、规模标签**，仅在数据库为空时首次自动灌入，之后不会覆盖用户数据
- `recruiting_open` 和 `recruiting_url` 不编造——这两个字段时效性强、容易过时或失效，种子数据里留空，实现完成后另外用 WebSearch 核实一批，其余由用户在页面里手动补充/修正

## 错误处理

- 后端用 Pydantic 做必填字段校验；HTMX 请求校验失败时返回局部错误提示片段，不整页报错
- 删除公司级联提示关联投递记录数量，避免误删/孤儿数据

## 测试策略

单用户本地小工具，不追求高覆盖率：
- 少量 pytest 覆盖核心逻辑：Application 增删改、公司级联删除、seed 脚本幂等性（重复启动不重复插入）
- 不做前端 UI 自动化测试
- 验收标准：手动在浏览器过一遍关键路径——建公司 → 建投递 → 改进度 → 简历模块增删改复制

## 明确不做的事（本期范围外）

- 多用户账号/登录
- 简历自动解析（AI/OCR），本期是手动粘贴+手动划分模块
- 简历模块多版本变体
- 云端部署
- 自动爬取公司招聘信息
- 投递进度的历史时间线（只存当前阶段，不记录阶段变更历史）
